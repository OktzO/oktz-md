## Bentuk data asli (temuan yang membatalkan asumsi awal)

Kolom `data` di Turso **bukan protobuf biner**. Semuanya JSON, dan untuk `session` **double-encoded** (butuh 2× `JSON.parse`):

```json
{"_sessions":{"<baseKey b64>":{"registrationId":892825949,"currentRatchet":{
  "ephemeralKeyPair":{"pubKey":"…","privKey":"…"},"lastRemoteEphemeralKey":"…",
  "previousCounter":0,"rootKey":"…"},"indexInfo":{"baseKey":"…","baseKeyType":1,
  "closed":-1,"used":1791111010852,"created":1791111010852,"remoteIdentityKey":"…"},
  "_chains":{"<ratchetKey b64>":{"chainKey":{"counter":0,"key":"…"},"chainType":1,
  "messageKeys":{}}}},"version":"v1"}
```

Konsekuensi: **risiko "SessionRecord v6 vs decoder v1" yangtertulis di RISKS R1 TIDAK BERLAKU.**
Tidak ada binary protobuf yang perlu di-reencode. Semua field kripto (`rootKey`,
`chainKey`, `ephemeralKeyPair` termasuk `privKey`, `remoteIdentityKey`, `messageKeys`)
tersedia sebagai base64, dan `LegacySessionV1` di wacore-libsignal memetakan **1:1**.

## Catatan penting untuk RISKS R1

Analisis awal (v6-vs-v1, Lapis 2/3) **tidak berlaku** untuk kasus ini. Risiko sebenarnya
yang tersisa jauh lebih kecil:

- **Lapis 1 (struktural `creds.json` → `DeviceStore`)** — belum diuji. Spike ini hanya
  mengimpor **sesi per-kontak**; pemetaan creds device belum dikerjakan.
- **Lapis "connect tapi pesan tak terbaca"** — **belum bisa dibuktikan tanpa akun WA uji.**
  Impor berhasil secara struktural ≠ decrypt berhasil. Ini yang harus Oktz uji.

## Edge case nyata di data produksi

`baseKeyType` = `0` pada **85 dari 538 sesi (16%)**. Enum Baileys: `0=UNKNOWN, 1=OUR_OWN,
2=OUR_DEVICE, 3=BOUND_TO_PEER, 4=BOUND_TO_SELF`. `LegacySessionBaseKeyRoleV1` cuma punya
`Local(1)`/`Remote(2)`.

**Keputusan: map 0/3/4 → `Local`, jangan dibuang.** Dasar (verifikasi source
`wacore-libsignal-0.7.0/src/protocol/legacy_session.rs:798`): satu-satunya pemakaian
`base_key_role` adalah validasi `Remote && pending_pre_key.is_some() → error`. Importer
selalu `pending_pre_key = None`, jadi check itu tidak pernah aktif → nol dampak ke decrypt,
dan 16% sesi produksi tetap terpakai. Kalau suatu saat `pending_pre_key` mulai diisi,
keputusan ini harus diulang.

`chainType` = 0 (PREKEY): **0 kemunculan** di data nyata. Chain PREKEY (kalau ada) tidak
punya padanan role V1 dan akan di-skip.
